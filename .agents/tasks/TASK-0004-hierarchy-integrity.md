# TASK-0004 层级与跨项目完整性

## 目标

本地和服务端拒绝跨项目父子关系、自引用和循环引用，移动条目后保持分组与父节点一致。

## 所属核心流程

创建分组、创建/编辑/移动条目、恢复数据库。

## 本次范围

- PostgreSQL 复合外键约束和写入前校验。
- SQLite 触发器和 Repository 校验。
- 跨项目、自引用、循环测试。

## 不在本次范围

- UI 树拖拽重做和任意深度性能优化。

## 操作角色

- 本地用户和服务端编辑者。

## 前置状态

- 项目、分组和条目已经存在。

## 成功结果

- 每个分组父节点、条目分组和条目父节点都属于同一项目；父条目与子条目处于同一分组；层级无环。

## 失败结果

- 非法关系返回明确错误，数据库不发生部分更新。

## 数据表

- `knowledge_groups`、`knowledge_entries`。

## API / 页面

- 保持现有 API，细化 409 错误。

## 事务要求

- 校验和更新在同一事务/SQLite 写操作内完成。

## 审计日志

- 本阶段不新增审计事件。

## 测试用例

- 跨项目分组、父条目、自引用、两节点循环、跨项目移动均失败。
- 合法创建、移动和重排继续成功。
