# 统一资产存储核心需求

## 目标

- 正文图片与项目附件统一抽象为 `Asset`，业务内容只保存稳定资产引用，不感知物理存储驱动。
- Electron 本地个人库支持本机目录和用户配置的 S3 兼容存储。
- 官方云与自部署服务共用服务端资产接口，服务端支持文件系统和 S3 兼容存储。
- 数据库记录是资产业务状态的权威来源，文件系统/S3 通过状态机和可重试任务实现最终一致性。
- 备份和恢复不得静默删除未内嵌的大文件。

## 核心规则

- 一个二进制文件由 SHA-256 标识内容，同一工作空间内允许安全去重。
- `Asset` 至少包含：id、workspaceId、kind、originalName、mimeType、sizeBytes、sha256、storageDriver、objectKey、status、createdAt、updatedAt。
- 正文图片与托管附件都引用 `assetId`；本机绝对路径和 URL 仍是外部链接，不冒充托管资产。
- 存储驱动只负责 put/get/stat/delete，不决定权限、引用关系和删除时机。
- 删除业务对象只释放资产引用；物理删除由可重试清理任务执行。
- 备份包含 manifest。缺少文件本体时必须明确报告，不能通过替换整个目录隐式删除现有文件。

## 非目标

- 本阶段不做 CDN、图片转码、病毒扫描和跨工作空间秒传。
- 本阶段不迁移服务端技术栈。
- 本阶段不新增多人协作能力。
