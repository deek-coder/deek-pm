# Deek PM 产品框架

## 核心定位

Deek PM 是桌面端项目资料管理工具，用于管理项目说明、账号密码、本地文件链接、线上入口、交接备注等信息。

产品支持两类工作空间：

- 本地个人库：固定一个，免登录，数据在本机。
- 服务端空间：可以有多个实例，需要登录，支持成员、邀请、权限、审计。

官方云和私有化部署都属于服务端空间。二者使用同一套服务端 API 和前端逻辑，区别只是服务地址、认证来源、部署位置。

## 信息架构

```txt
进入应用
  -> 选择工作空间实例
    -> 本地个人库
    -> 官方云服务空间
    -> 自部署服务空间
  -> 当前工作空间
    -> 项目
    -> 智库
    -> 成员与邀请，服务端空间才有
    -> 备份与恢复，本地空间才有
    -> 空间设置
```

## 产品原则

- 工作空间是实例，不是简单类型。
- 本地库通常只有一个，不需要账号登录。
- 服务端空间可以有多个，官方云和自部署都是服务端空间。
- 自部署只改变 Base URL、认证来源和部署环境，不改变 UI 架构。
- 进入工作空间后，左侧只展示当前空间内功能。
- 切换工作空间必须是明确动作，不能做成右上角随手切换。
- 本地空间不展示成员、邀请、团队权限。
- 服务端空间展示成员、邀请、角色、权限和审计。
- UI 不直接关心本地或服务端，统一调用 Repository 接口。
- UI 应该像桌面生产力工具，避免传统后台管理系统质感。
- 优先使用自有设计系统，不让第三方组件库决定产品气质。
- 开发模式按成熟团队标准推进：类型优先、分层清晰、Mock 先行、安全默认、文档同步。

## 推荐架构

```txt
React UI
  -> Application Service
    -> Repository Interface
      -> LocalRepository
      -> ServerRepository
```

LocalRepository 面向本机数据库和文件能力。

ServerRepository 面向 HTTP API。官方云和自部署共用 ServerRepository，只切换 Base URL 和认证配置。
